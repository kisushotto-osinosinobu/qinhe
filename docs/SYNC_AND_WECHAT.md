# Web、小程序同步与微信条件

## 同步方式

Web 与小程序只调用同一个 `/api`，后端只连接同一个 MySQL。商品、库存和订单没有前端各自的演示副本：

- Web 页面进入或点击刷新时重新请求数据；关键写操作成功后立即重载列表。
- 小程序商品、订单、个人中心和员工库存页在 `onShow` 时重新请求；列表支持下拉刷新。
- 小程序提交订单后由后端事务直接写入销售单、预占库存和流水，Web 下一次刷新即可读取。
- Web 改商品/库存、收款、取消或退货后，小程序重新进入页面或下拉刷新即可读取最新值。

这是基于请求时读取的最终一致展示，不使用 WebSocket。关键写操作的一致性不依赖前端刷新：数据库事务、行锁、条件更新、订单/退货幂等键和流水唯一键共同保证不会重复扣减或恢复库存。

## 微信小程序工程

源码位于 `miniapp`，通过 uni-app 编译为原生微信小程序目录，不是手机尺寸网页。已包含账号登录/注册、分类搜索、详情、购物车、提交订单、本人订单/详情/取消、个人中心/退出，以及员工库存和预警。

构建：

```powershell
Set-Location miniapp
pnpm install --frozen-lockfile
pnpm typecheck
pnpm build:mp-weixin
```

在微信开发者工具导入 `miniapp/dist/build/mp-weixin`。仓库使用 `touristappid` 方便无凭据构建；它不能用于真机发布。

## 真机联调与上线所需外部条件

当前未执行真机验证、微信审核或发布。要完成这些步骤，需要项目所有者提供/完成：

1. 已认证的小程序主体和真实 AppID，将其写入本地 `manifest.json` 或构建环境，不提交 AppSecret。
2. 一台可公网访问的后端服务器和受信任 HTTPS 证书。
3. 在微信公众平台配置 `request` 与 `uploadFile` 合法域名；域名通常还需按所在地要求备案。
4. 将小程序 API 地址改为该 HTTPS 域名，并在服务器限制 CORS、配置生产 JWT 密钥、数据库账号和持久化上传目录。
5. 微信开发者工具登录有权限的开发者账号，预览/真机调试，随后上传代码、提交审核并由管理员发布。

当前没有实现微信身份登录，也没有伪造授权成功。账号密码能完成开发联调。若以后增加微信身份，应由小程序取得临时 `code`，服务端携 AppID/AppSecret 调用真实 `code2Session`；AppSecret 只能保存在服务端密钥配置中。

## 真机验收建议

先在 Web 以库存管理员修改某商品库存，在手机小程序商品页下拉刷新并核对可售量；再用会员下单，在 Web 销售订单刷新确认同一订单号；Web 收款后回到小程序订单页刷新核对状态。每一步同时检查库存台账和流水。
