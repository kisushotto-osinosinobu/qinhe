# 角色权限与业务状态

权限在 Spring Security 方法级规则中执行，前端菜单和按钮只是体验优化。`ADMIN`、`INVENTORY_MANAGER`、`CASHIER`、`MEMBER` 是固定基础角色；公共注册永远创建 `MEMBER`，员工角色只能由管理员分配。

## 权限矩阵

| 能力 | 管理员 | 库存管理员 | 收银员 | 普通会员 |
| --- | :---: | :---: | :---: | :---: |
| 分类/商品查询 | ✓ | ✓ | ✓（商品） | 仅公开在售商品 |
| 分类/商品维护与图片上传 | ✓ | ✓ | — | — |
| 分类删除 | ✓（无关联商品） | — | — | — |
| 供应商、采购入库 | ✓ | ✓ | — | — |
| 库存/预警/流水查询 | ✓ | ✓ | ✓ | — |
| 手工出入库、盘点 | ✓ | ✓ | — | — |
| Web 收银、收款、退货 | ✓ | — | ✓ | — |
| 小程序下单、查看/取消本人订单 | 可用 | 可用 | 可用 | ✓ |
| 查看所有销售单与统计 | ✓ | 统计/订单查询 | ✓ | 仅本人订单 |
| CSV 导出 | ✓ | — | ✓ | — |
| 用户、角色、配置、审计 | ✓ | — | — | — |

员工从小程序访问库存接口仍由后端角色校验；普通会员调用同一接口返回 403。会员读取订单详情时额外比较 `member_id`，不能通过猜测 ID 访问他人订单。

## 订单状态

```text
PENDING_PAYMENT --收款--> PAID --部分退货--> PARTIALLY_RETURNED --退完--> RETURNED
       |
       +--取消--> CANCELLED
```

- 小程序下单生成 `PENDING_PAYMENT` 并增加预占库存；Web POS 可在同一事务中直接模拟收款。
- 收款把预占库存和当前库存同时扣减；取消仅释放预占库存。
- 退货只允许 `PAID` 或 `PARTIALLY_RETURNED`，回补当前库存，不产生预占；累计退货量不能超过原销售数量。
- `CANCELLED` 与 `RETURNED` 都是终态。重复取消、重复采购确认返回当前结果，不重复改变库存。

## 采购状态

```text
DRAFT --确认入库--> WAREHOUSED
   |
   +--取消--> CANCELLED
```

确认入库在事务中锁定采购单，逐项写入库存和不可重复的业务流水；`WAREHOUSED` 再次确认不会二次入库。

## 库存口径与并发

- 当前库存 `current_qty`：账面实物数量，受采购、销售、退货、手工出入库和盘点影响。
- 预占库存 `reserved_qty`：待付款订单锁定但尚未出库的数量。
- 可售库存：`current_qty - reserved_qty`。

下单、收款、取消、入库和退货均使用数据库事务；库存行使用 `SELECT ... FOR UPDATE`，更新语句还带有非负与 `reserved <= current` 条件。库存流水以 `(product_id, business_type, business_ref)` 唯一约束防止重复记账。订单和退货使用客户端幂等键并有唯一索引。

## 销售统计口径

净销售额 = 已收款订单的 `paid_amount - refund_amount`。只统计 `PAID`、`PARTIALLY_RETURNED`、`RETURNED`；待付款和已取消订单不计入。热销数量使用销售数量减已退数量。历史明细保存商品编码、条码、名称、规格、单位、成交价与金额快照，后来改价不会影响历史订单。
